# Traffic Game — план разработки

Референс: Trafficity (трейлер разобран покадрово с шагом 0,5 с, описание из Steam). Игра — градостроитель только про дороги
и трафик: игрок строит сеть, агентная микросимуляция машин проверяет её на прочность.
Наше дополнение к референсу: **редактор уровней** (обводка реальной карты по подложке, например GTA III / Vice City)
и **кампания головоломок**.

**Платформа:** WebGL, в первую очередь CrazyGames (ПК + мобильный браузер); интеграция с площадками — через **PrimeSDK**
(`https://github.com/Prime-SDK/PrimeSDK.git`), который покрывает и Yandex Games, GameDistribution, Poki и др. Unity 6000.5.2f1, плоская процедурная 2D-графика.
**Языки:** RU, EN, PT (pt-BR), DE, ES, TR.
**Ориентация:** альбомная — основная, книжная — поддерживается (адаптивный UI, см. §3).
**Репозиторий:** приватный, коммерческий проект, лицензия — All rights reserved (см. §6).

## 1. Механики референса (что видно в трейлере)

**Инструменты строительства**
- Дорога: прямая или кривая, цена и угол у курсора, пунктирные направляющие (продолжение, «Parallel», «Perpendicular»), привязка к узлам. 0–1 с, 10–13 с
- Сетка кварталов в 3 клика: угол → противоположный угол → шаг, под любым углом. 1–2 с, 26 с, 31 с, 33 с
- Проверки с понятной причиной отказа: красное превью и подпись (`self_overlap`, `extension_failed`, «Can't place row of buildings»). 2–2,5 с, 4 с
- Кольцо: ставится кругом поверх существующих дорог и само к ним подключается. 3 с
- «Add lane»: дорисовка полосы вдоль существующей дороги — съезды, полосы разгона, карманы для поворота. 17–19 с, 37–38 с
- Высота (Elevation 0–3): эстакады с тенью, рампы, развязки до 4 уровней. 7 с, 12–15 с, 49–52 с, 66–68 с
- Многополосные дороги и шоссе с разделителем, дороги одностороннего движения.
- Светофоры (точки на стоп-линиях), фазы, защищённый левый поворот. 24–26 с
- Редактор соединений полос: точка-цвет на каждой входящей полосе, стрелки к выходящим, разворот. 53–54 с

**Город и спрос**
- Жильё S/M/L (зелёное), офисы (фиолетовые), магазины и ТЦ (синие), промышленность (оранжевая/серая, грузовики), добыча сырья.
- Здания ставятся рядом вдоль дороги, у каждого свой выезд; есть счётчик доступных. 3,5–4,5 с
- Жителям нужны магазины и работа, они не любят шум и загрязнение; заводам нужны рабочие и сырьё, магазинам — покупатели
  и товары. При повышении уровня города игрок получает пачку новых зданий.
- Радиус влияния при размещении (30,5 с); оверлеи шума и загрязнения, недовольные здания перекрашиваются (43–44 с).

**Симуляция:** маршрут выбирается с учётом пробок, машины перестраиваются в карманы и выезжают из очередей, грузовики длиннее легковых.

**Карты:** процедурный генератор, 4 биома (умеренный, пустыня, зима, острова), 3 уровня сложности. 44,5–46 с

## 2. Архитектура (MVP)

```
 ┌─────────── TrafficGame.Core (без UnityEngine, только Unity.Mathematics) ───────────┐
 │ Geometry   Безье/дуги, длина дуги, offset-кривые, полигоны, пересечения             │
 │ Roads      RoadNetwork: Node, Segment(curve, RoadProfile, elevation), Junction      │
 │            Validation → BuildResult{cost | error code}                             │
 │ Lanes      LaneGraph из сети: Lane, LaneConnection, ConflictPoint, SignalGroup      │
 │ Simulation фикс. тик, IDM, смена полосы (MOBIL), приоритеты, светофоры              │
 │ Routing    A* по графу полос, стоимость = время + загруженность                     │
 │ City       здания, спрос на поездки, (позже) ресурсы, счастье, шум, загрязнение     │
 │ Levels     LevelData (JSON, schemaVersion), цели, ограничения, (позже) генератор    │
 │ Commands   ICommand + UndoStack                                                    │
 └────────────────────────────────────────────────────────────────────────────────────┘
 ┌─────────── TrafficGame.Presentation (без UnityEngine) ─────────────────────────────┐
 │ Presenters инструментов, симуляции, HUD, карточек, меню                             │
 │ Интерфейсы view, IInputSource, ILocalizer (presenter отдаёт ключ + аргументы,       │
 │ view подставляет перевод)                                                          │
 └────────────────────────────────────────────────────────────────────────────────────┘
 ┌─────────── TrafficGame.Views (MonoBehaviour) ──────────────────────────────────────┐
 │ Меши дорог/рельефа, RenderMeshInstanced для машин и зданий, оверлеи, камера,         │
 │ UI Toolkit + адаптивные хосты карточек, адаптер Input System (мышь + тач)            │
 └────────────────────────────────────────────────────────────────────────────────────┘
 ┌─────────── TrafficGame.App ────────────────────────────────────────────────────────┐
 │ GameBootstrap — единственная точка сборки; режимы; сохранения;                      │
 │ IPlatformService → PrimePlatform (PrimeSDK): реклама, события геймплея, сохранения, │
 │ язык, звук, пауза                                                                  │
 └────────────────────────────────────────────────────────────────────────────────────┘
 TrafficGame.Editor, TrafficGame.Tests (EditMode: Core + Presentation)
```

Принципы:
- **Core и Presentation без UnityEngine** (кроме Mathematics — в Unity 6.5 это модуль движка; граница проверяется тестом `AssemblyBoundaryTests`): логика покрывается быстрыми EditMode-тестами без сцены.
- **Инструмент = presenter + команда**: ввод → превью + `BuildPlan` → проверка в Core (цена или код ошибки) → `ICommand` с undo.
- **Без DI-фреймворка и синглтонов**: зависимости передаются через конструктор, всё собирает `GameBootstrap`.
- **Симуляция детерминированная**: фиксированный тик, struct-of-arrays, без выделения памяти в горячем цикле, view
  интерполирует. Цель — ≥ 3000 агентов при 60 FPS в WebGL на ПК. Burst — только по данным профайлера.
- **Графика процедурная и unlit**, без сторонних ассетов. Данные в JSON (`schemaVersion`), баланс в ScriptableObject.
- **PrimeSDK — только в `App` за `IPlatformService`**; в Core и Presentation его нет (см. §4а).

## 3. UI, ориентация, локализация

**Адаптивные карточки** (закладываются с первого окна):
- Любое окно (свойства дороги, светофор, здание, статистика, настройки) — это `Card`: один UXML-шаблон, один presenter.
- Два хоста карточек с общим интерфейсом `ICardHost`:
  - `BottomSheetHost` — книжная/узкая ориентация: карточка выезжает снизу, свайп закрывает, внутри скролл;
  - `FloatingHost` — альбомная: окно можно перетаскивать за заголовок, позиция запоминается, есть ограничение по краям экрана.
- Хост выбирается по соотношению сторон и переключается на лету при повороте или ресайзе. Presenter'ы про это не знают.
- Тулбар: снизу в книжной ориентации, сбоку или снизу в альбомной (USS-классы `.portrait` / `.landscape` на корне). Учитывается safe area.
- Чего не делаем: докинг, ресайз окон, сохранение раскладки между устройствами — дорого и почти не нужно.
- Ввод: мышь (ЛКМ — строить, ПКМ/СКМ — двигать камеру, колесо — зум) и тач (тап, pinch-zoom, двумя пальцами — pan/rotate,
  тап-удержание — контекст). Превью инструмента на таче подтверждается кнопкой ✓.

**Локализация** — собственный лёгкий JSON-локализатор (решение этапа 2: пакет Unity Localization тянет Addressables и асинхронную загрузку):
- По файлу `<код>.json` на язык; никаких захардкоженных строк в UI (сначала RU + EN, остальные — на этапе контента). Тест проверяет, что во всех языках одинаковые ключи.
- Язык при первом запуске — строго `PrimeSDK.Language.Current` (требование модерации площадок), иначе EN; потом — переключатель в настройках.
- Шрифт Inter (OFL) — кириллица, турецкие ı/İ/ğ/ş, португальские/испанские/немецкие символы проверены.
- Числа и деньги форматируются по культуре языка; в данных и сейвах — только `InvariantCulture`;
  регистр строк — без culture-зависимого `ToUpper` (турецкая İ).
- Тексты ошибок инструментов — ключи (`error.road.self_overlap`), переводятся в view.

## 4а. PrimeSDK — правила интеграции
По документации PrimeSDK 5.1.53. Пример обёртки в наших проектах — `~/WormsBase/Assets/Game/Platform/Runtime/PrimePlatform.cs`.
- Ставим на **этапе 0**: SDK работает полноценно, только если весь платформенный API проекта идёт через него.
- Старт: `PrimeSDK.CreateInstance()` → `WaitForProviders(...)`; до колбэка SDK не трогаем. `Analytics.GameIsReady()` вызываем,
  когда главное меню уже интерактивно.
- `GameplayStart` — вход в уровень или снятие паузы; `GameplayStop` — меню, пауза, экран результата; `GameplayRestart` — перезапуск уровня.
- **Никогда не трогаем `Time.timeScale` и `AudioListener` напрямую**: только `PrimeSDK.Time.Scale` / `PrimeSDK.Audio`.
  Скорость симуляции ×1/×2/×4 — наш собственный множитель поверх `deltaTime`, поэтому системная пауза SDK (`timeScale = 0`)
  автоматически останавливает и симуляцию.
- Сохранения: `PrimeSDK.Data.SetString(key, json, important: false)` + один `Save()` в точках сохранения; формат — наш версионированный JSON.
- Реклама: interstitial — между уровнями, rewarded — за бонус (например +бюджет или подсказка). `onAdBlockDetected` на CrazyGames →
  `PrimeSDK.Pause.ShowContinuePrompt()`.
- `Achievements.HappyTime()` — при победе на уровне (CrazyGames).
- WebGL-шаблон `PrimeGames`; флаги `PORTRAIT_ONLY` / `LANDSCAPE_ONLY` не ставим — поддерживаем обе ориентации.
- Свой `.jslib` (загрузка подложки, буфер обмена) с API площадок не взаимодействует — так конфликта с SDK нет.
- Проверка размера сборки — Build Optimizer из PrimeSDK Toolkit.

## 4. Этапы

Каждый этап — срез, который можно запустить. В конце: компиляция чистая, тесты зелёные, я присылаю изменённые файлы,
шаги проверки и скриншот. **Ты проверяешь → коммит и пуш → следующий этап.** WebGL-сборка — только на ★.

### Фаза A — вертикальный срез (понять, о чём игра)

Цель среза: базовый цикл «построил дороги → посмотрел на трафик → увидел пробку → исправил» на 3 небольших уровнях,
в браузере, в обеих ориентациях, на RU/EN.

**Этап 0. Каркас**
- Проект 6000.5.2f1: URP (2D Renderer), Input System, Unity.Mathematics, Test Framework, Newtonsoft JSON, UI Toolkit.
- asmdef'ы по схеме, `GameBootstrap`, сцена `Game`, ортографическая камера (мышь + тач).
- PrimeSDK + шаблон PrimeGames, `IPlatformService` / `PrimePlatform` (инициализация, язык, время, звук, сохранения).
- `ProjectSetup` (editor-меню) с настройками WebGL; git + LFS, `.gitignore`, README, `LICENSE` (All rights reserved).
- **Проверка:** проект открывается, камера работает в обеих ориентациях, тест-заглушка зелёный.

**Этап 1. Дорожная сеть: модель и отрисовка**
- `RoadNetwork`, 2 профиля (2 и 4 полосы, двустороннее движение), граф полос, геометрия перекрёстков.
- Меши: полотно, бордюр, разметка, стрелки. Загрузка уровня из JSON.
- **Проверка:** тесты геометрии и графа; тестовая сеть выглядит как в трейлере.

**Этап 2. Строительство и каркас UI**
- Дорога (прямая/кривая, привязки, направляющие, цена/угол), бульдозер, смена профиля, кольцо. Валидация с кодами ошибок, undo/redo.
- Каркас UI: тулбар, HUD (деньги, скорость), `Card` + оба хоста, локализация RU/EN.
- **Проверка:** строю сеть в альбомной и книжной ориентации, карточка свойств дороги работает в обоих режимах.

**Этап 3. Симуляция трафика**
- IDM, смена полосы под маршрут, A* с учётом загруженности, нерегулируемые перекрёстки (уступи / главная), кольцо,
  защита от взаимной блокировки. Рендер инстансингом, пауза и ×1/×2/×4.
- **Проверка:** тесты симуляции (машины доезжают, нет deadlock'а на кольце), замер FPS в редакторе при 1000/3000 машин.

**Этап 4. Срез собран ★**
- Здания на уровне (жильё, работа, магазины) как источники и цели поездок, генерация спроса.
- Цель уровня: «перевези N машин за T минут, не превысив бюджет»; оверлей пробок; экран победы/поражения.
- 3 уровня-головоломки, меню выбора уровня, сохранение прогресса локально.
- **Проверка:** WebGL-сборка, играем на ПК и телефоне → **решаем, что развивать дальше** и в каком порядке идёт фаза B.

### Фаза B — глубина (порядок уточним после среза)

**Этап 5. Перекрёстки** ✓ — светофоры с адаптивными фазами (пропуск пустых фаз, продление зелёного, жёлтый и all-red,
правый поворот на красный), защищённый левый поворот, стрелки полос (редактор соединений через стрелки), разметка:
стоп-линии, «зубцы» уступи дорогу, цвет сигнала на стоп-линии, стрелки на асфальте. Дальше по желанию: ручные фазы
и длительности, обучающий уровень со светофором.

**Этап 5а. Дизайн UI** ✓ — Material 3 (как во Flutter-приложениях), светлая и тёмная темы для всей игры (UI и карта),
режим «как в системе» по умолчанию; макеты UI «Traffic Game UI»; масштаб как uGUI «scale with screen size /
expand» (референс 1280×720 / 390×844 по соотношению сторон), векторные иконки из SVG-путей, камера на старте уровня показывает
все здания. Дальше: шрифт Figtree (OFL) вместо Inter по желанию.

**Этап 5б. Плавность** ✓ — ничего не меняется за один кадр: переходы цветов, появление/скрытие, нажатия, ползунок
сегментов, счётчик денег, звёзды; шторка при смене сцены; инерция камеры и плавный зум; плавная смена скорости;
машины проявляются и растворяются; подсветка пробок и смена темы карты плавные; из карточки уровня можно вернуться
к списку. Дальше по желанию: плавное появление и снос дорог.

**Этап 6. Высота и шоссе** — уровни 0–3, рампы, тени, «Add lane» (съезды, карманы), шоссе с разделителем,
сетка кварталов в 3 клика, пресеты развязок (ромб, клеверный лист, турбина). Части:
- 6а. Высота — уровни 0–2 по 5 м, рампы с ограничением уклона, пересечение без перекрёстка через целый уровень,
  мосты рисуются поверх дорог и машин, тени и бортики, переключатель высоты у типов дорог и кольца;
  уровни 5 «Эстакада» и 6 «Над перекрёстком».
- 6б. Шоссе с разделителем и «Add lane».
- 6в. Сетка кварталов в 3 клика, пресеты развязок.

**Этап 7. Экономика города** — жильё S/M/L, офисы, магазины, промышленность, сырьё, грузовики; счастье, шум, загрязнение;
оверлеи; размещение зданий рядами вдоль дороги; уровни города и пачки зданий.

**Этап 8. Карты и редактор** — рельеф (вода, горы, песок, трава, снег), процедурный генератор (4 биома × 3 сложности),
редактор уровней с подложкой-картинкой, цели и ограничения, экспорт и импорт файлом или кодом.

**Этап 9. Режимы и мета ★** — Город (генератор + рост), Головоломки (звёзды), Песочница; сохранение городов.

**Этап 10. Контент и локализация** — 12–15 головоломок, 2–3 большие карты «в духе» известных городов
(оригинальные названия, без чужих картинок и логотипов), переводы на PT/DE/ES/TR.
